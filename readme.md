# 🎯 推理服务接口文档

## 概述

本接口用于接收 HTTP 请求，通过后台逻辑转发给 WebSocket 模型服务进行推理，并将结果流式发送到目标 WSS 地址。

---

## 📌 接口信息

- **请求方式**：`POST`
- **请求路径**：`/`
- **请求内容类型**：`application/json`
- **返回类型**：`application/json`

---

## 📥 请求参数

### 顶层字段

| 参数名        | 类型    | 是否必填 | 说明                                                        |
|---------------|---------|----------|-------------------------------------------------------------|
| `uuid`        | int     | 是       | 用户唯一标识 ID                                              |
| `session_id`  | int     | 是       | 当前会话 ID                                                  |
| `model`       | string  | 是       | 模型具体名称，如 `"gpt-3.5-turbo"`                           |
| `class`       | string  | 是       | 模型平台类别，如 `"chatgpt"`、`"deepseek"`、`"tongyi"` 等   |
| `URL`         | string  | 否       | 目标 WebSocket 地址（适用于部分模型，如第三方私有部署）     |
| `api_key`     | string  | 否       | 模型平台的 API Key（如 OpenAI 使用场景）                     |
| `parameters`  | object  | 否       | 推理参数配置（详见下方说明）                                 |
| `prompt`      | string  | 是       | 当前用户请求内容（用于参数校验，真实内容从历史中构造）      |

### `parameters` 对象字段

| 子参数名       | 类型    | 默认值 | 是否必填 | 说明                               |
|----------------|---------|--------|----------|------------------------------------|
| `temperature`  | float   | 0.7    | 否       | 模型输出的随机性，值越大回复越多样化 |
| `type`         | string  | "chat" | 否       | 对话类型，支持 `"chat"`、`"image"`、`"audio"`、`"video"` |

---

## 📤 响应数据

成功响应：

```json
{
  "errorcode": 0
}
```

失败响应示例：

```json
{
  "errorcode": 3002,
  "message": "缺少必要参数: uuid, session_id"
}
```

### 错误码说明

| 错误码         | 说明                                  |
|----------------|---------------------------------------|
| `0`            | 成功                                  |
| `3001`         | 请求体不是合法 JSON                   |
| `3002`         | 缺少必要参数                          |
| `3003`         | 服务内部处理异常                      |

---

## 🔄 WSS 推理内容格式说明

在模型推理过程中，服务端将通过 WebSocket 客户端连接，将推理结果流式发送至目标 WSS 地址。为提高兼容性和简化解析，传输内容为纯字符串格式，按如下顺序发送：

---

### 1. 推理分析段（Reasoning）

如果存在模型推理过程的解释部分，将首先发送如下标签作为开头：

```
Reasoning:
```

接下来将分多次发送推理过程内容，每段为字符串，按顺序发送。

发送完成后使用如下提示符：

```
######@@@@@@%%%%%%
```

---

### 2. 最终回答内容（Contents）

模型主回答部分前置如下标签：

```
Contents:
```

然后依次发送内容片段，发送完成后使用如下提示符：

```
&&&&&&******^^^^^^
```

---

### 3. 结束标记

所有内容发送完成后，发送如下字符串作为结束标志：

```
*^%$%&&$$$$$$%^^$##E%##^^$#$%
```

---

## ✅ 示例

假设模型返回一个 reasoning 和一个 content：

**发送顺序如下：**

```
Reasoning:
模型正在分析你的问题……
分析表明该问题与……相关。
######@@@@@@%%%%%%
Contents:
这是我给出的回答内容。
&&&&&&******^^^^^^
*^%$%&&$$$$$$%^^$##E%##^^$#$%
```
